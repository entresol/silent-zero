# The broker

> The only component that hands out authority: capability patterns, CaMeL and FIDES, why model-based defences fail, three agent-OS designs for the same job, CaMeL between agents; nothing proven yet; the industry’s agent sandboxes grant by resource.

Design · LLM reviewed · updated 2026-11-21 · 31 sources · https://silentzero.ooo/wiki/design/broker.html

The only component in Silent Zero that hands out authority. It grants capabilities that are attenuated, time-limited and revocable, and it words every request a human sees, so the agent never does. It runs isolated and still belongs to the trusted base, because its decisions are the guarantee. It will be *tested* first, with *proven* as the target (paper, Section 3).

## What it must do

- Bind each permitted action to recipients, data and parameters, enforce that at every tool call, and define revocation for actions under way (paper, Section 5).
- Word approval requests in a form the agent cannot imitate (paper, Section 5).
- Our reading: grant the least authority that serves a person's intent, and never decide on the strength of a model's judgement of untrusted text.

## The paper and its sources

- Section 2.4 cites [The Confused Deputy](https://silentzero.ooo/wiki/sources/1988-hardy-confused-deputy-or.html.md) for the confused deputy, [The Attacker Moves Second](https://silentzero.ooo/wiki/sources/2026-nasr-attacker-moves-second.html.md) for the twelve broken defences and [Robust Composition](https://silentzero.ooo/wiki/sources/2006-miller-robust-composition-towards.html.md) for passing authority as capabilities. All three confirmed; Nasr et al. say the defences were broken "either fully or substantially". The step from confused deputy to prompt injection is the paper's own analogy; [Indirect prompt injection](https://silentzero.ooo/wiki/sources/2023-greshake-not-what-you.html.md), cited for the phenomenon, confirms the phenomenon and does not use the term. Section 6 limits the analogy: capabilities bound how far a deceived agent reaches.
- Table 1 cites [Defeating Prompt Injections by Design (CaMeL)](https://silentzero.ooo/wiki/sources/2025-debenedetti-defeating-prompt-injections.html.md): "77 % of tasks with provable security versus 84 % undefended". The figure is confirmed. Our reading: "provable" in CaMeL means a formally stated property that holds by construction under a correct interpreter and correct policies; nothing is formally proven, so "secure by design" would be the accurate wording. The same row names FIDES ([Securing AI agents with information-flow control](https://silentzero.ooo/wiki/sources/2025-costa-securing-ai-agents.html.md)), which enforces information flow rather than capabilities; the figures in the row are CaMeL's.
- Section 6 cites [Securing AI agents with information-flow control](https://silentzero.ooo/wiki/sources/2025-costa-securing-ai-agents.html.md) for adding information-flow control to capabilities. Confirmed for what information-flow control does; the pairing with capabilities is the paper's step. FIDES leaves implicit flows open, which fits the paper's point that data leaks through allowed channels. See [Information-flow control](https://silentzero.ooo/wiki/concepts/information-flow-control.html.md).

The IBM position paper lists tool mediation and identity as platform primitives, proposes classing calls as reversible, compensable or irreversible with stronger authorization for the last, and names fine-grained, context-dependent authorization as open. It specifies this for a cloud substrate, and nothing in it is verified ([Towards an Agent Operating System](https://silentzero.ooo/wiki/sources/2026-steinder-towards-agent-operating.html.md), §IV.D, §IV.H).

## Related

- [KataOS](https://silentzero.ooo/wiki/systems/kataos.html.md) put seL4 under machine-learning devices in 2022, with a dynamic root server rather than a static system ([Announcing KataOS and Sparrow](https://silentzero.ooo/wiki/sources/2022-google-announcing-kataos-sparrow.html.md)).
- [Cohesix](https://silentzero.ooo/wiki/systems/cohesix.html.md) is a neighbouring design on seL4: models and agents stay on the host, and target-side role, ticket, lifecycle and bounds checks decide what is accepted ([Cohesix, a research operating system for edge AI](https://silentzero.ooo/wiki/sources/2026-bower-cohesix-research-operating.html.md), landing page only).

- [AgentKernel](https://silentzero.ooo/wiki/sources/2026-zou-agentkernel-trust-native.html.md) is a design for the same job on a conventional host kernel: an external monitor outside the model, delegation that can only narrow a child's capabilities, and information-flow labels on memory. Its model-based classifier and eBPF enforcement rest on the host operating system, which the authors assume enforces them correctly, and they defer proofs of their invariants (design paper, partly read). Our reading: the host is not a verified kernel.
- [AgenticOS](https://silentzero.ooo/wiki/sources/2026-zhao-agenticos-intent-oriented.html.md) proposes the job as an intent filter: an agent declares a manifest, and only the semantic calls it names exist in its capsule, with capability tokens, label checks and a gateway that keeps credentials. It is a conceptual architecture with no implementation, and its kernel is assumed to be formally verifiable or intensively audited (design paper, read in full).
- [Agent libOS](https://silentzero.ooo/wiki/sources/2026-zhang-agent-libos-runtime.html.md) is a library above a conventional host that admits an operation only when a live process, a capability, the task ceiling, policy or a person's approval, a budget and a primitive all agree, and checks information flow separately, with a person's one-shot release for conditionally permitted high-sensitivity egress. Its own suites pass, on scripted plans and one model; the host, the Python interpreter and the storage are trusted (design paper with evaluation, read in full). See [Agent operating systems](https://silentzero.ooo/wiki/concepts/agent-operating-systems.html.md).
- [MCP-38](https://silentzero.ooo/wiki/sources/2026-shen-mcp-38-comprehensive.html.md) catalogues 38 threats to systems built on the Model Context Protocol, many of them ways in which text persuades a model, the rest classical flaws. Our reading: for the first kind the broker need not recognise the text, since it grants only declared authority, which limits reach but not leakage through allowed channels; the paper offers no evidence on that and the broker is not built.
- [Agent Operating Systems](https://silentzero.ooo/wiki/sources/2026-sharma-agent-operating-systems.html.md) proposes an agent operating system as a control plane over Linux or Windows: model output is a proposal, tool calls pass deny-by-default capability checks, and a registry admits tools found at run time. It is a design without implementation, measurements or proofs, and it names no real-time goal. It lists sequences of individually allowed actions as a gap: per-action enforcement is "necessary but not sufficient" and stateful evaluation may be needed (§8.2), which is the open question on sequences below.
- [the AOS reference architecture](https://silentzero.ooo/wiki/sources/2026-sharma-agent-operating-system.html.md), by the same authors, adds a reference architecture with two planes. Its delegation rule says a child grant may not exceed its parent's permissions, scope, budget or validity interval, and it says revocation of a disconnected task "may not be instantaneous". It names TLA+ checking of such rules as future work, none done; read in part (§12.6, §16.8).
- [MOSAIC](https://silentzero.ooo/wiki/sources/2026-wu-mosaic-knowledge-guided.html.md) measures attacks that carry no explicit malicious instruction: benign command-line steps that pass state to each other through files, environment and hooks. Progent and CaMeL, run as hooks over an agent's tool calls, left their success rate unchanged at 96.63 per cent in the authors' setup on Claude Code. They explain it by the state passing between commands and not through tool-call arguments (CaMeL ran there as an adapted trace monitor). Our reading: a broker that checks tool calls cannot be the whole guarantee; what the agent's domain shares with other components must be bounded below it, by the capabilities it holds. See [The static system](https://silentzero.ooo/wiki/design/static-system.html.md).
- [AgentOS](https://silentzero.ooo/wiki/sources/2026-liu-agentos-application-silos.html.md) is a vision paper for a personal agent OS with an "Agent Kernel" above a legacy kernel. Its security idea is a semantic firewall that checks intent and marks untrusted data as tainted; in the sections read it has no implementation and no capability mechanism. Our reading: another design in the line of [AgentKernel](https://silentzero.ooo/wiki/sources/2026-zou-agentkernel-trust-native.html.md) and [Agent Operating Systems](https://silentzero.ooo/wiki/sources/2026-sharma-agent-operating-systems.html.md), with checks on intent where the broker has checks on authority.
- [ToolFence](https://silentzero.ooo/wiki/sources/2026-li-toolfence-fine-grained.html.md) is a tool-layer monitor that binds each sensitive argument to a provenance, with a model writing the policy from the user's request and a model judge granting what it missed. Our reading: it comes close to the paper's wording on binding actions to recipients, data and parameters, with a model in the grant path, which differs from a broker whose decisions are the guarantee; the evidence is AgentDojo's fixed attacks.
- [Causality laundering](https://silentzero.ooo/wiki/sources/2026-chinaei-causality-laundering-denial.html.md) argues that denied calls leak, since an agent can infer from a refusal what exists and pass it on later. It is a single-author preprint with three constructed scenarios, and the paper does not say what the broker returns on a refusal. Our reading: an agent that holds no capability to an object has no name to probe, which would narrow the channel; this is design intent and not a result of the source.

- [Can CaMeLs Talk?](https://silentzero.ooo/wiki/sources/2026-peters-gill-can-camels.html.md) shows that CaMeL's guarantee does not carry over when one agent calls another as a tool: the parent's instruction text can carry untrusted data into the child's planner. The authors fix it with a trusted message and a separate data channel, in trees of agents only. Our reading: the paper has several untrusted agents and does not discuss agents calling each other; if Silent Zero lets agents delegate, the instruction a delegating agent writes is a channel the broker would have to control.
- [PACE, provenance-aware capability enforcement](https://silentzero.ooo/wiki/sources/2026-li-pace-provenance-aware.html.md) checks each tool call against a capability compiled from the authenticated request, with a minimum cut over declared flow edges; it names request compilation, effect labels and complete mediation as premises it does not prove: a tested mediator, not a proven one.
- [CaMeLoT, a static check of an agent's plan on top of CaMeL](https://silentzero.ooo/wiki/sources/2026-nikolaou-camelot-camel-orchestrated.html.md) adds a static temporal check of CaMeL's plan before any tool runs.

- [OpenShell](https://silentzero.ooo/wiki/systems/openshell.html.md) and [Microsoft Execution Containers (MXC)](https://silentzero.ooo/wiki/systems/mxc.html.md) are the industry's sandboxes for agents, on Linux, Windows and macOS. MXC states that its policy "remains outside the agent workload's control"; for OpenShell, rules are approved "from outside the sandbox", which is our reading of the same idea. OpenShell denies outbound traffic by default ([Kernel-level agent security in OpenShift AI 3.5](https://silentzero.ooo/wiki/sources/2026-red-hat-beyond-container-boundaries.html.md)), resolves opaque credential placeholders only at authorised endpoints ([NVIDIA: Overview of OpenShell](https://silentzero.ooo/wiki/sources/nd-nvidia-openshell-overview.html.md)), and lets the agent propose a rule that a person reviews, or that four automatic checks approve for low-risk changes ([Kernel-level agent security in OpenShift AI 3.5](https://silentzero.ooo/wiki/sources/2026-red-hat-beyond-container-boundaries.html.md)). MXC states the principle that "an agent cannot be its own security authority" and offers a learning mode that records what a workload tried before enforcement ([Execution Containers, policy-driven containment for AI agents](https://silentzero.ooo/wiki/sources/2026-microsoft-execution-containers-policy-driven.html.md)). Our reading: they cover part of what the paper's Section 6 says hardening leaves out, namely credentials and outbound traffic, by policy and with no proof, and they do not describe the per-call binding to recipients, data and parameters that Section 5 asks of the broker; the paper's wording will need to say so.

## Open

- The integrity proof the broker relies on is not stated for MCS, and Microkit always uses MCS. Until it is, the kernel's guarantee under the broker is functional correctness only. See [The kernel](https://silentzero.ooo/wiki/design/kernel.html.md).
- CaMeL's policies are defined by its engine; users, tool providers or automatic derivation are envisaged later ([Defeating Prompt Injections by Design (CaMeL)](https://silentzero.ooo/wiki/sources/2025-debenedetti-defeating-prompt-injections.html.md), §5.2, §10). For Silent Zero: who writes them, and from what?
- [CaMeLoT, a static check of an agent's plan on top of CaMeL](https://silentzero.ooo/wiki/sources/2026-nikolaou-camelot-camel-orchestrated.html.md) adds a pre-execution model check of the plan (nuXmv, CTL) behind CaMeL's run-time checks; the rules are written by hand, and task rules are derived from the prompt via typed obligations. It reports no attack-success figures (preprint; coverage and agreement with CaMeL only).
- OpenShell lets the agent draft the rule it asks for, while the paper has the broker word every request a person sees so that the agent never does. Whether an agent-written proposal can be safe to show, and what the four automatic checks guarantee and against which model, the sources do not say ([Kernel-level agent security in OpenShift AI 3.5](https://silentzero.ooo/wiki/sources/2026-red-hat-beyond-container-boundaries.html.md)).
- Blocked calls go to a person, and too many approvals breed fatigue ([Defeating Prompt Injections by Design (CaMeL)](https://silentzero.ooo/wiki/sources/2025-debenedetti-defeating-prompt-injections.html.md), §9.2). In CaMeL's STRICT mode policies fired in about half the tasks run without attack, with wide differences between task suites (Appendix D). The paper adds that requests must be worded so the agent cannot imitate them, which needs a trusted path to a screen.
- When a task is to act on instructions found in data, isolating the planner alone cannot help; policies and capabilities must carry the load ([Defeating Prompt Injections by Design (CaMeL)](https://silentzero.ooo/wiki/sources/2025-debenedetti-defeating-prompt-injections.html.md), §6.4).
- Whether Silent Zero agents may call other agents, and what the broker then sees of the instruction passed between them ([Can CaMeLs Talk?](https://silentzero.ooo/wiki/sources/2026-peters-gill-can-camels.html.md)). The source covers trees of agents only.
- Sequences of individually allowed calls may add up to a harmful one, as return-oriented programming chains allowed code fragments ([Defeating Prompt Injections by Design (CaMeL)](https://silentzero.ooo/wiki/sources/2025-debenedetti-defeating-prompt-injections.html.md), §9.3). A 2026 preprint reports such chains through shared system state succeeding against deployed coding agents in the authors' constructed attacks ([MOSAIC](https://silentzero.ooo/wiki/sources/2026-wu-mosaic-knowledge-guided.html.md)); whether Silent Zero leaves an agent any such state is open.
- CaMeL leaks through loops and exceptions unless restricted, with a residual exception path; its authors do not exclude timing channels ([Defeating Prompt Injections by Design (CaMeL)](https://silentzero.ooo/wiki/sources/2025-debenedetti-defeating-prompt-injections.html.md), §7). In Silent Zero the same holds one level down; see [Time protection](https://silentzero.ooo/wiki/concepts/time-protection.html.md).
- What the broker tells an agent when it refuses a request. A denial that names a cause or a category can disclose what the agent may not read ([Causality laundering](https://silentzero.ooo/wiki/sources/2026-chinaei-causality-laundering-denial.html.md), §3); ToolFence returns an explicit denial with a diagnostic message by design ([ToolFence](https://silentzero.ooo/wiki/sources/2026-li-toolfence-fine-grained.html.md), §3.1). The paper is silent on it.
- Revoking authority over a lost connection fails unsafe; a grant should lapse by itself when the broker cannot reach it ([Robust Composition](https://silentzero.ooo/wiki/sources/2006-miller-robust-composition-towards.html.md), §11.5.3).
- In Microkit a called server must finish in bounded time, unenforced ([seL4 Microkit: User Manual, v2.3.0](https://silentzero.ooo/wiki/sources/nd-sel4-microkit-user-manual.html.md)); the broker has to meet that.
